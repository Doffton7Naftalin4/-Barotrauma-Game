## Что установлено чтением кода

### Геометрия палуб

В `DUGONG_DECK_LAYOUT` описаны три элемента:

- индекс 0 — `upper`;
- индекс 1 — `main`;
- индекс 2 — `lower`.

Необходимо отдельно сверить пользовательскую нумерацию «палуба 1/2» с этими индексами и фактической геометрией. Не делать вывод о соответствии только по названию массива.

### Выбор палубы в addLeak()

Текущая сигнатура:

```js
function addLeak(room, size, lx, top, deckHint)
```

Если `deckHint` не передан, `targetDeck` выбирается из `top`:

- `top === true` → индекс 1;
- `top === false` → индекс 2.

Таким образом, обычный вызов без `deckHint` не выбирает индекс 0. После выбора палубы функция пытается найти отсек по X через `dugongRoomSpecAt(targetDeck, lx)`. Если отсек не найден, используется запасное соответствие `dugongDamageSpot(room)`, основанное на `DUGONG_LEGACY_FLOOD_MAP`.

### Передача данных из crash()

Текущая функция:

```js
function crash(imp, x, top) {
  if (imp > 28 && tcool <= 0) {
    tcool = 1;
    hurt(imp * 0.07);
    var leak = addLeak(roomOf(x), 0.5, x, top);
    sfx.hit();
    if (leak) spark(sx + leak.lx, sy + leak.y, 10);
  }
}
```

Явный индекс палубы в `addLeak()` не передаётся.

В обработчике движения:
- при вертикальном столкновении `top` определяется выражением `svy < 0`, то есть направлением движения;
- при горизонтальном столкновении `top` выбирается случайно через `Math.random() < 0.5`.

Это подтверждает, что текущий путь столкновения не определяет палубу по точной геометрической точке контакта. Но для окончательного объяснения переноса повреждений нужно проследить все обработчики урона и сверить индексы с пользовательской нумерацией.

### Визуальная пробоина и внутреннее затопление

`addLeak()` хранит отдельно:
- `deck` и `room` — определённый отсек/палубу;
- `waterRoom` — индекс внутреннего помещения, которое будет затапливаться;
- `lx`, `y`, `top` — визуальное положение и сторону эффекта.

Цикл затопления увеличивает `dugongFlood[L.waterRoom]`. Следовательно, фактическое поступление воды привязано к `waterRoom`, тогда как визуальная точка пробоины рассчитывается через другие поля записи. Если привязки не согласованы, визуальная пробоина может не соответствовать помещению, которое наполняется водой.

Пользовательское наблюдение о струе, выглядящей направленной наружу, зафиксировано как отдельная визуальная проблема. Нельзя менять скорость затопления, пока не проверена связь отверстия с помещением за ним.

4. При вертикальном столкновении `top` выводится из направления движения.
5. Визуальные координаты и индекс внутреннего затопления представлены разными полями.
