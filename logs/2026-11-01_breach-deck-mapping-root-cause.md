# Дополнение: точная причина регрессии выбора палубы для пробоин

- Дата: 2026-11-01
- Связанный коммит: https://github.com/Doffton7Naftalin4/-Barotrauma-Game/commit/ff20f2504adad7fc88436e82123fd6c2e20dee06
- Проверяемая сборка: `Barotrauma_Dugong_World_Repair_flood-rate-balanced.html`
- Blob SHA сборки: `b3527f6a292053d50158ad011ce5a6467eb23d97`

## Что именно сломалось

В коммите `ff20f2504adad7fc88436e82123fd6c2e20dee06` функция `addLeak()` была изменена так, что при наличии координаты удара выбирает палубу по булевому признаку `isTop`:

```js
var targetDeck = isTop ? 1 : 2;
```

Но `isTop` вычисляется как сравнение вертикальной координаты удара с центром подлодки (`m.y < sy`), а не как реальная идентификация палубы. В результате удар классифицируется только как палуба 1 или 2; верхняя палуба с индексом 0 вообще не может быть выбрана этой веткой. Координата X затем выбирает ближайший отсек только внутри уже ошибочно выбранной палубы.

В более поздней сборке функция принимает `deckHint`, однако проверенные вызовы при ударах монстров, укусах и столкновениях передают `lx` и булев `top`, но не передают фактическую палубу. Поэтому наличие параметра `deckHint` само по себе проблему не исправляет.

## Почему это связано с ремонтом

Запись пробоины получает `deck`, `room`, `waterRoom`, `lx` и визуальную координату `y` из выбранного отсека. Ремонт ищет пробоину на текущих палубе и в отсеке игрока. Если палуба/отсек назначены неверно, видимая пробоина и доступная для сварки цель расходятся. Визуальная координата также принудительно ставится на край палубы через `dugongEffectY()`, а не на точную точку удара.

## Правильное направление исправления

Не выбирать палубу по `m.y < sy`. Передавать фактическую координату удара X и Y в локальной системе подлодки, определять ближайший допустимый отсек по обеим координатам и использовать один и тот же объект пробоины для отображения, затопления и ремонта. Для старых событий, у которых точка удара неизвестна (например, стартовые повреждения и сейсмические события), сохранить безопасный fallback по явно заданному отсеку.

## Статус

Это подтверждённая статическим чтением кода причина неверного выбора палубы; исправление ещё не внесено и игровой тест не выполнялся. Не считать задачу закрытой до резервной копии, отдельной сборки, проверки синтаксиса и игрового теста на всех трёх палубах.
